# WorkBuddy 模型目录的跨平台方案

此前系统只信任 CLI 的 `--help` 模型列表。在本机，安装包 CLI 的默认帮助只有 9 个选项；WorkBuddy 客户端的当前目录包含较新的模型。单独追加硬编码模型名或拷贝某台 Windows 的缓存，都不能解决以后换机或更新的问题。

## 现在的行为

1. 自动发现 standalone CodeBuddy CLI 或 WorkBuddy 内置 CLI；Windows 使用 APPDATA/LOCALAPPDATA/ProgramFiles，macOS 检查标准应用目录、用户应用目录和应用标识，支持改名后的 WorkBuddy。
2. 读取 `WORKBUDDY_CONFIG_DIR` 或当前用户 `.workbuddy` 中的账号快照及当前账号的产品模型目录，不合并其他账号。
3. 只选择支持工具调用且位于客户端 CLI 允许列表中的模型。客户端的完整目录可能还有图片模型、补全模型或不属于 CLI 的模型，不直接全部放进剪辑模型菜单。
4. 在 LiveCut 用户缓存中生成仅含模型定义和 CLI 模型允许列表的配置。查询帮助和实际 AI 调用使用同一配置；V1、V2、V3 均覆盖。认证、服务地址、客户端命令和其他配置不复制，不修改客户端原文件。
5. CLI 确认失败时保留客户端目录、安装包目录或内置参考目录，并在设置中明确显示来源；目录出现不代表账号拥有实际调用权限，授权仍由 WorkBuddy 服务端检查。

系统设置新增“刷新模型列表”。刷新绕过五分钟的目录缓存；客户端目录、账号或安装文件变化也会自动使缓存失效。旧的已保存模型即使暂时不在目录中，也保留选择，不静默改为 auto。

## 换机使用

安装并打开 WorkBuddy，完成账号登录，使客户端更新自己的模型目录。启动新版 LiveCut，选择 WorkBuddy，点击“刷新模型列表”，选择模型并保存。

一般不需要修改代码或手动复制模型清单。非标准安装可指定 `WORKBUDDY_CLI` 或 `WORKBUDDY_INSTALL_DIR`；自定义客户端数据目录可指定 `WORKBUDDY_CONFIG_DIR`。如果 PATH 中没有 Node，尝试使用 WorkBuddy 已安装的托管 Node。显式提供的 `ACC_PRODUCT_CONFIG_*` 配置保持优先，不被我们的目录配置覆盖。

这里刷新的是客户端当前目录，并不会授予额外模型权限，也不保证 WorkBuddy 未更新的本地目录已经包含服务端所有新模型。先更新/登录客户端，再刷新 LiveCut。

### CLI 返回空内容与登录状态

模型目录可读不代表 CLI 已能使用登录凭据。2026-10-12 的 macOS 实际日志中，独立 CLI 报 `AuthenticationRequiredError`，同时出现加密凭据读取的 `category=missing-key`，最终以退出码 0 返回空 stdout。LiveCut 现在在空响应时检查当前工作目录、当前进程和本次启动时间匹配的 CLI 日志，只提取登录错误标记，不展示日志内容或复制凭据。其他进程和旧日志不会被当作本次错误。

遇到明确的登录错误，先在 WorkBuddy 重新登录；若独立 CLI 仍无法识别，启动该 CLI 并执行 `/login`，按提示完成认证，再重启 LiveCut 并重试失败阶段。当前机器的 CLI 启动命令为：

```sh
"/Applications/AI/WorkBuddy.app/Contents/Resources/app.asar.unpacked/cli/bin/codebuddy"
```

这项处理改善错误识别，不会绕过客户端的凭据加密，也不会自动进行模型调用。

## 验证

本机 macOS 实测从 9 个选项恢复为 21 个（20 个 CLI 模型加自动选择），含 GLM 5.3/5.3 Flash、DeepSeek V4.1 Flash、Kimi K3。系统设置返回的 ID 集合与实际执行命令使用的 CLI 帮助列表一致。原账号快照和产品模型文件校验值保持不变。

全量回归 390 项通过、3 项跳过、4 项子测试通过；后续专项 75 项通过。覆盖 Windows 安装路径、Windows Node 启动、macOS 改名安装、账号隔离、目录更新、刷新、失败回退、配置透传和 V2 用量限制。

浏览器测试覆盖保留已保存模型、刷新后新模型可选/可保存、刷新中切换提供方，以及 320/390/1280 像素宽度无横向溢出。使用临时 API 数据，没有修改生产设置或发起付费模型调用。本次未在 Windows 实机重新运行或生成安装包。

## 修改设置后的旧任务

每次执行保存 AI 引擎、提供方和模型快照，以保证同一次执行中不因全局设置变化而切换。手动重试、重启和重跑节点现在会读取最新系统设置并更新快照，保留旧配置审计；暂停恢复和自动执行下游节点保留本次快照。任务详情显示“本次 AI 配置”。

曾出现设置为 WorkBuddy/hy3、旧任务快照仍为 auto/auto 的情况，导致重试自动选择 OpenCode。已修复重试配置更新逻辑，并校正本机三个相关失败任务的快照，没有发起模型请求。
