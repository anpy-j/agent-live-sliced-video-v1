# V1 S4 气口检测

入口：规则管理 → 气口检测。流程开关默认关闭，独立保存到应用数据目录的 `data/rule_pipeline.json`，不影响另外三个规则开关。仅 V1 接入，V2/V3 不变。

开启后，在 S4 完成选句和口头词清理之后、渲染之前分析原音。关闭后严格跳过检测，不加载词级数据、不启动音频分析、不修改入选区间、不生成气口快照；S4 的口头词报告版本标识也不受气口开关影响。重新执行 S4 会按当前开关重新生成编排；仅重新渲染复用当次 S4 保存的切点，不重新检测，也不因切换开关重算历史结果。

## 检测范围

当前实现是保守的声学停顿切点校准，不是专门的吸气声分类模型。使用 FFmpeg `silencedetect` 分析每段首尾各一秒内的原音，寻找低于 −38dB、持续至少 120ms 且接触片段边缘的停顿。检测后保留 80ms 自然停顿，每端最多收紧 600ms；至少保留 300ms 片段。持续低音量的整个分析窗口、连续语音和片段内部停顿不剪切。

结合 S1 词级时间戳保护正文：允许在 ASR 首尾词块估计边界内最多校正 120ms，并保留首尾词块的主体。缺少可用词级数据、没有可靠停顿或调整不足 15ms 时保持原切点，并在报告中说明原因。只在原入选范围内收紧，不扩展到淘汰语句。支持虚拟时间线的素材路径、源时间和速度映射。

开启时 `order.json` 与 `manifest.json` 保存 `breath_detection`，包含原区间、检测后区间、逐段原因、参数和结果摘要。重渲染校验原始入选区间、摘要和切点合法性；失配时要求重新执行 S4。背景音乐、较响的吸气声或 ASR 时间戳偏差可能使保守策略保留原切点，应通过原音对比确认实际效果。

## 任务试匹配

选择一个已完成 V1 任务，点击「生成对比视频」。以该任务 `manifest.json` 中全部最终物理片段为输入，保留原顺序，独立生成：

- 检测前、检测后的完整片段合集。
- 每个交付片段的检测前、检测后视频；同一交付片段跨素材的物理区间按原分组拼接。
- 全部物理区间的切点明细、调整数量和减少时长。

检测前视频按任务保存的原切点重新编码，与检测后使用相同编码设置，不是原素材整段录像。页面支持逐段播放、视频下载、处理进度和刷新恢复；同一时刻只播放一个视频以便听音对比。开关关闭也能测试，测试不调用 AI、不更新生产任务、不覆盖原素材或成片。结果独立存储于 `data/breath_trials/<id>/`。

接口：`GET /api/rules/breath/jobs`、`POST /api/rules/breath/test`、`GET /api/rules/breath/trials/<id>`，以及该地址下的 `before.mp4`、`after.mp4` 和逐段视频。测试异步执行，一个服务实例同一时刻只运行一个气口测试；服务重启后未完成测试会显示中断，可重新生成。

验证：`python -X utf8 -m unittest tests.test_breath tests.test_rule_pipeline tests.test_filler_rules`；`node tests/breath-ui.test.cjs`。使用临时数据目录和 FFmpeg 合成素材，不修改用户任务或规则。真实直播素材仍需在页面中听音比较，不以合成样本测试替代听审。
