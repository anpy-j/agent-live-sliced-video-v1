# S4 逻辑复核

本次为只读检查，没有修改筛选代码、任务或已导出视频，没有调用真实模型。检查发现四处缺口；现有测试通过不能据此认定内容安全或完整句群绑定已经充分实现。

## 1. 句群标识未传递到分段导出（高优先级）

`compile_selection` 保留 group，但 `build_segments`、`build_virtual_segments` 丢弃它，`group_segments_for_export` 只根据片段 id 分组。一个 section 包含源时间 0–2 秒的“这件马甲”和 2.1–4 秒的“是羊毛的，穿着很软”，会成为两个导出文件。两片同属 group=0，但因为有 0.1 秒间隔，不能合并成单一源区间，导出也未将两片拼为一个完整句群。

建议：将明确的 S4 group 标识传到物理片段，并按该标识拼接导出。不要用扩大源区间代替拼接，以免夹带被删除内容。旧任务缺少 group 时保持原有导出方式。

## 2. 句群内部倒序仍可通过（高优先级）

同一 context 中 ID 0 为“这件马甲”，ID 1 为“是羊毛的，穿着很软”。`sections=[{role:selling_point,ids:[1,0]}]` 与 `ordered_ids=[1,0]` 会通过 `_validate_order`。`compile_selection` 只是不合并，仍按倒序渲染，没有拒绝这种改变原句含义的重排。

建议：同一完整表达中的依赖子句须遵守源顺序；独立完整表达之间允许调整顺序。至少对同一 context 内的倒序设置确定性校验。

## 3. 跨片段硬禁词未检查（高优先级）

“这是原”与“版的材质”分别放在两个 section，`compile_selection` 对每个 clip 检查均不命中硬禁词，最终拼接文本却是“这是原版的材质”。同一组内只要因时间缺口未合并，也存在同类问题。

建议：单句检查之外，按最终播放顺序对完整输出文本再次检查统一硬禁词表；首次渲染与重渲染共用此校验。

## 4. 淘汰原版参照后，承接句仍进入无参照候选池（中优先级）

真实《格雷日记》中 ID 2、3 提及原版，被筛除；ID 4、5、6 仍保留，ID 6 为“完全是一模一样的而且都是高克重的克重非常的高”。它被标记为新的 context，但模型输入没有参照内容，也没有被淘汰原因。提示词虽然要求删除原版比较的承接句，输入不足以让模型可靠识别该关系。

这证实了输入信息缺口，不等同于证实真实模型必然会再次选中该句。

建议：对断点附近提供有严格数量上限的原始邻句，标明“仅供理解、不可选”及淘汰原因，或由上游输出依赖标记。不要把所有原始 ASR 和淘汰理由重新全量送入 S4。

## 已成立的改进

新版候选不再强制捆绑整个 S3 句单元。新版入选快照能防止重渲染重新合并夹带淘汰句；旧任务读取保留淘汰句断点，失配 ID 明确报错。每份素材仍只需一轮 S4。以上四处缺口不否定这些改进，但需要补齐后再做真实模型内容验收。
