# V1 规则流程开关

“规则管理”的每个 Tab 提供独立流程开关，配置保存在当前应用数据目录 `data/rule_pipeline.json`。本次仅控制 V1，固定接入阶段，不提供任意修改阶段的入口。

| 模块 | 接入阶段 | 初始开关 | 开启后的行为 |
| --- | --- | --- | --- |
| 拼音限制 | V1 S2 | 开 | 使用已保存且启用的拼音规则筛除命中子句 |
| 重复限制 | V1 S2 | 关 | 在基础粗筛后检测重复，仅筛除后续完整重复子句 |
| 口头词清理 | V1 S4 | 开 | 编排完成后全文拼音匹配，按精确词级时间戳清理每条规则设定范围（句首或全部）内的命中 |

初始开关保持此前行为：原有拼音和口头词规则继续执行；新接入的重复限制需人工开启。单条拼音、口头词规则的启停与模块流程开关独立：正式流程要求模块开关和单条规则都开启；试匹配可在模块关闭时执行，也可显式选择已停用的单条规则。

重复限制的试匹配条件与生产条件分开保存。点击“保存当前检测条件到 V1 S2”才更新生产检测条件；调整试匹配表单不会自动影响后续任务。短语和颜色信息点重复仅记录，不据此删除整个子句。完整重复子句必须整体归一化相同，保留时间序中首次出现，只有包含正文完整重复的后续子句才删除。含有其他独有内容的子句保留。

三个开关都不改变阶段顺序、阶段职责、模型调用结构、任务调度或基础粗筛。原 S2 的违禁词、时长、场控、病句和基础去重继续执行。V2/V3 和整片优化 V3 的规则行为不受本次 V1 开关影响。

配置在执行对应阶段时读取并保存快照：S2 使用 `s2-rule-pipeline.snapshot.json`，S4 使用 `order.json.filler_cleanup.integration`。改变开关或规则不自动重新计算历史结果：拼音、重复需重新执行 S2 并继续后续阶段；口头词需重新执行 S4。只重渲染仍沿用保存的 S4 文本和切点。

API：`GET /api/rules/pipeline` 读取全部开关；`PUT /api/rules/pipeline/{pinyin|repetition|filler}` 更新单个模块，接受布尔 `enabled`，重复模块还可接收 `options`。单模块更新不会覆盖其他模块配置。`version`、`stage` 若提供必须匹配固定的 V1 阶段，否则拒绝保存。

验证命令：

```powershell
python -X utf8 -m unittest tests.test_rule_pipeline tests.test_filler_rules
node tests/filler-ui.test.cjs
node tests/rules-ui.test.cjs
```

新增测试覆盖三个开关独立持久化、启用与关闭后的实际 S2/S4 行为、关闭后的试匹配、完整及部分重复保护、全流程与单节点重跑阶段顺序、S4 快照复用、V2/V3 隔离，以及真实 HTTP 后端上的页面开关、条件保存与刷新恢复。
