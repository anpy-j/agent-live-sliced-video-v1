# LiveCut 独立剪辑模块与桌面端 0.2.0

## 使用流程

1. 进入侧栏“人工剪辑”，新建项目，或从已完成的 V1 任务创建项目。
2. 导入本地视频、音乐、PNG/WebP/GIF 贴纸。桌面端使用系统文件选择窗口；浏览器版可粘贴本地绝对路径。
3. 点击“加入时间线”，或拖动素材到对应轨道。拖动片段移动，拖动左右边缘修剪。
4. 可新建、复制、重命名时间线，分别做不同版本。每条时间线可以有多个视频、音频、图片、字幕轨。
5. 选中片段，用播放头定位，再分割、删除、波纹删除、复制或分离音频。锁定轨道阻止片段修改；波纹删除会移除所有轨道的同一时间区间，受影响的锁定轨道会阻止操作。
6. 添加手工字幕、导入 SRT，或选择有声音的片段后“识别选中片段字幕”。识别后增加字幕轨，不覆盖已有字幕，需人工校对。
7. 设置转场、特效、音量、淡入淡出以及后处理，最后导出当前时间线。后台排队导出，可取消，完成后在桌面端打开文件位置。

编辑自动保存，支持撤销重做；撤销历史只保留在当前打开的窗口。多窗口旧版本保存会被拒绝，避免覆盖新编辑。

## 功能与资源

| 功能 | 本版能力 | 素材来源 |
| --- | --- | --- |
| 时间线 | 多时间线、多轨、分割、修剪、删除、拼接、波纹删除、复制、锁定、静音、显隐、帧步进 | 本地视频及 V1 成片 |
| 转场 | 叠化、滑入、擦除；“与前段重叠形成转场”自动对齐 | 内置 FFmpeg 处理 |
| 特效 | 暖色、冷色、黑白、模糊；缩放、位置、旋转、不透明度 | 内置滤镜 |
| 字幕 | 白字黑边、黄色强调、半透明底条、简洁细字、粗体标题、逐字高亮；时间、位置、字号与文字可改 | 内置样式；手工输入、SRT、faster-whisper |
| 贴纸 | 图片及 GIF，可放在图片轨道 | 用户导入有使用权的素材 |
| 音频 | 多轨音乐、原声分离、静音、音量、淡入淡出、变速 | 用户导入音乐及原片音轨 |
| 后处理 | 1% 默认不透明度画中画、四角只露少量贴纸、预留底部 6 像素的进度条 | 导入的视频、图片与内置进度条 |

“分离音频”只把视频原声移到音频轨并静音原视频，尚未实现 AI 人声分离。AI 音乐生成也未接入。本版没有剪映素材商城、剪映专用字幕模板或剪映草稿导入。动态贴纸和字幕预览与 FFmpeg 排版可能存在差异，以导出成片为准；暖色、冷色实时预览是近似效果。逐字高亮按字幕时长平均分配字时长，尚未使用逐词识别时间。视觉转场不自动对音频做交叉淡化，音频淡入淡出可单独设置。

视频预览优先使用 H.264 MP4，音频优先 WAV/AAC；部分 MKV/AVI 编码浏览器无法直接解码，需要先转换。超长时间线、大量并行片段仍需要实际素材压测。

后处理是画面装饰，不能保证平台去重结果。1% 透明度仍会轻微改变像素；进度条将完整画面高度微缩后留底边，不裁掉或覆盖底边内容。

## 设置与保存位置

系统设置分为“运行环境 / AI 配置 / Skill 管理 / MCP 接入 / 剪辑与导出 / 桌面应用”六个 tab。V3、S2 标注入口已隐藏，原代码和接口保留。

“剪辑与导出”中设置完成版目录，例如 Windows 的 `D:\切片\袁艺灵\完成版`。默认输出到用户 `Movies/LiveCut`。导出为 H.264 MP4 + AAC，默认 192 kbps、44,100 Hz，音视频同时导出。

字幕识别默认 CPU/int8 的 small 模型，首次使用需要联网下载模型；也可填写本地 CTranslate2 Whisper 模型目录。安装包包含识别运行库，不包含模型权重。模型识别耗时取决于素材时长和电脑性能。

人工剪辑数据库独立保存于工作目录的 `data/editor/editor.db`，与 V1 分开。导出冻结项目快照，之后继续编辑不会改变正在导出的内容。素材保留在原路径，移动或改写后需要重新导入。

桌面端默认工作目录位于 Electron 用户数据目录下的 `workspace`。可在“桌面应用”tab 切换工作目录并重启，以连接原来的 LiveCut 项目目录；切换前请保存编辑并结束正在运行的任务。不会自动复制或迁移旧项目。`LIVECUT_WORKSPACE` 环境变量优先于保存的目录配置。Windows/macOS 使用文件锁阻止两套服务同时操作同一工作目录。

首次启动自动分配本地端口，并写入桌面配置；之后重启沿用该端口，方便 MCP 客户端保持连接地址。端口被占用时应用会报告启动失败，可通过 `LIVECUT_DESKTOP_PORT` 指定新端口（设为 0 重新自动分配）。

## 开发与打包

需要 Node.js 22.12+、Python 3.12、目标主机上的 FFmpeg 与 FFprobe。

```powershell
npm ci
python -m venv .runtime/desktop-build
.runtime/desktop-build/Scripts/python.exe -m pip install -r desktop/requirements-build.txt
npm run desktop
npm run test:editor
npm run test:desktop
npm run dist:win
```

macOS 在 Mac 上执行：

```sh
npm ci
python3 -m venv .runtime/desktop-build
.runtime/desktop-build/bin/python -m pip install -r desktop/requirements-build.txt
npm run dist:mac
```

构建脚本自动选择 `.runtime/desktop-build` 环境；也可使用 `LIVECUT_BUILD_PYTHON` 指定构建 Python。未创建环境时 Mac 使用 `python3`。Mac 需使用不依赖 Homebrew 外部 dylib 的独立 FFmpeg 构建。本次仅在 Windows x64 验证；macOS 构建配置已提供，需要在对应架构 Mac 上构建和启动验证。

打包只收集前端、本地后端、必要运行库、Skill 初始文本及 FFmpeg，不收集用户数据库、日志、模型、API 密钥或个人素材。运行数据写入用户目录，不写入安装目录。签名和公证尚未配置，构建使用 `--publish never`，不自动上传 GitHub，也不自动更新。

第三方许可文本随本地运行包保存于 `runtime/licenses`。FFmpeg 构建启用了 GPL 组件，公开分发时需同时履行对应许可与源代码提供要求，参考 FFmpeg 自带许可说明及 https://ffmpeg.org/legal.html。

构建工具依赖审计目前报告 8 个 moderate 级别的开发依赖问题，来自 electron-builder 的下载代理日志链；正式应用无 npm 生产依赖。未为消除报告而降级打包器。
