# 可选语义归组插件

规则管理 → 重复限制 → 语义归组插件。默认关闭。旧的 S2 重复限制流程开关及其“保留首次、剔除后续完整重复句”接入已移除；脚本试匹配保留为只读工具，基础粗筛原有的去重规则保持不变。当前只接入 V1 普通剪辑，V2、V3、成片重组不接入。

- 关闭：原 S1 → S2 → S3 → S4 → S5，不增加节点或 AI 调用，S3 契约和 S4 提示词保持原样，不读取旧分组缓存。
- 开启：S1 → S2 → S3 → **信息提取** → **语义归组** → S4 → S5。基础节点 ID、编号和职责保留，插件节点以 `+` 展示。

信息提取读取现有 `order_candidates` 合并后的完整候选，不调整 S3 提示词、判定结果、文本或时间戳。每批最多 60 个候选，提取对象、全部信息点、限定条件和是否可以独立播放。语义归组额外调用一次 AI，对所有候选全局归并，仅将同对象、同条件、全部重要信息等价且可以相互替代的候选归为互斥组。适用于任意评价、事实、卖点和建议，不为“好看”编写专用词表。否定、不同商品、颜色、部位、搭配及存在新增信息的候选不能仅因话题相同而合并；不确定时独立保留。

全部候选继续交给 S4；插件只追加“每个可替代组最多选一条，也可以不选”的约束。S4 结合完整性、开头、衔接、时长择优。程序在原 S4 契约校验边界检查组内冲突，不机械删除返回结果。校验失败走现有配置的备用模型机制，全部失败则该节点报错，不静默忽略约束，也不自动关闭插件。没有新增无限重试。

## 配置与快照

`GET /api/rules/pipeline` 返回 `features.semantic_groups`。通过 `PUT /api/rules/pipeline/semantic_groups` 保存 `{"enabled": true}`，接入阶段固定为 `S3–S4`，版本为 `v1`。

执行器在任务开始时将插件配置固定到任务目录的 `plugins.snapshot.json`。暂停恢复、单节点自动向后推进沿用同一快照，运行中切换全局配置不改变当前任务。新任务、完整重启、手动重跑非渲染节点采用当前设置；仅重新渲染继续使用已有 S4 结果。历史成片不会因切换开关而自动重算；历史任务保留其执行记录，下次手动重跑才更新可选节点。

插件结果独立存储：

- `plugins/semantic_groups/extract.json`：信息点、候选 ID、指纹、AI 调用数与耗时。
- `plugins/semantic_groups/groups.json`：可替代组、归组理由、指纹、AI 调用数与耗时。
- 启用时 `order.json.semantic_groups` 保存当次采用的组约束。

缓存指纹包含插件版本、模型、商品参考和全部候选的 ID、原文、时间、成员；分组另绑定信息提取结果。上游变化后重算。重跑 S4 可复用有效缓存；手动重跑信息提取清理提取和归组缓存，手动重跑归组只清理归组缓存。插件关闭时不复用这些文件。

新增 AI 调用通常为 `ceil(候选数 / 60) + 1`，S4 沿用现有调用但增加约束输入。耗时记录为真实墙钟时间；未接入提供商实际 token 用量统计，不将字符数当作已计费 token。此次验证使用 mock AI，真实归组质量和真实服务耗时仍需素材试运行验证。
