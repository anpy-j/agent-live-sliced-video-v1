# macOS 加密剪映草稿读取

已接入 macOS 本机剪映的 `libvideoeditor.dylib`，用 C++ 读取器处理 libc++ 字符串 ABI；Python 后台不直接加载这个库。独立子进程失败或超时会给出错误，不回退为假时间线，不改原草稿。返回内容必须是合法 JSON 对象。

V1、V2、V3 均通过原有草稿/时间线入口使用该读取能力；仅改进草稿读取基础设施，V1 的 `pipeline/` 和 `engine/` 算法目录保持原内容。原有整片优化模块也接入相同 macOS 读取器，Windows 解密入口保持原实现。

## 启用与环境

退出原桌面进程，再在项目目录运行 `npm run desktop`。无需手动清理历史失败缓存，macOS 草稿摘要的读取版本标记已更新。

按应用标识寻找剪映，改名后的 `.app` 也支持。非标准安装可以设置 `JIANYING_INSTALL_DIR` 为 .app 或 Frameworks 目录，或设置 `JIANYING_MAC_LIBRARY` 为 dylib 路径。显式路径无效会报错，不静默改用另一安装版本。

源码启动首次自动编译读取器，需 Xcode 命令行工具；后续使用按源代码和架构指纹缓存的二进制。桌面构建已加入读取器编译与打包，最终安装包不要求编译工具，但需要用户本机安装剪映。不会复制分发剪映的私有库。本次未重打包安装包。

## 验证结果（2026-10-12）

本机 Apple Silicon、剪映 11.3.0（应用名 VideoFusion-macOS.app）：

- 23 份真实根草稿全部成功解密为 JSON。
- 草稿 API 返回 23 条记录，22 条有可选时间线。
- 1 条记录的时间线本身没有视频轨道，明确显示“剪映草稿时间线为空，没有可剪辑的视频片段”。
- 样本草稿的两条时间线均可解析，素材路径实际存在。
- 冷草稿列表读取约 3.56 秒；Mac 限制两路并发。
- 全部 119 个原草稿文件的 SHA-256 校验值保持不变。
- 全量回归 374 项通过，2 项跳过，4 项子测试通过。包含实际编译的 C++ 桥与测试 dylib 的调用验证、失败/超时/JSON 校验、Windows 入口和打包资源测试。

没有调用付费模型、启动真实剪辑任务或修改用户草稿。该实现调用剪映私有接口，其他版本更新后可能需要适配；尚未在 Intel Mac 实机验证。
