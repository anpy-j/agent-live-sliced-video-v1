# V2 独立剪辑流程

剪映草稿页顶部、搜索左侧新增 V1/V2 按钮，页面首次加载默认 V1。切换只影响之后点击“开始剪辑”创建的任务，刷新草稿保留当前选择，整页重新打开恢复 V1。任务版本在创建时固定，重试、暂停恢复、重置和单节点重跑沿用该版本。

后台需要加载新代码。旧后台未声明支持 V2 时，前端禁用 V2 按钮，避免看起来选了 V2 实际运行 V1。代码更新不自动中断现有服务或剪辑任务；请在当前任务完成后重启后台。桌面打包入口已补充 V2 模块，本轮未生成新的安装包。

## V1 的隔离边界

- `agent_video/pipeline/` 和 `agent_video/ai.py` 保持本次修改前的文件内容，V1 的阶段序列、提示词、AI 调用和渲染调用不变。
- 数据库仅增加 `pipeline_version` 列，既有任务默认 `v1`，不重置历史状态、产物或版本。V2 的 `review` 阶段不会触发旧数据库归档。
- 任务执行器只在 `pipeline_version == 'v2'` 时加载 `agent_video/pipeline_v2`。V2 失败不会回退 V1。
- V2 内容产物、AI 请求缓存、用量和验收报告均位于该任务的 `v2/` 子目录。不同任务的工作目录本来就独立。
- 既有“爆款学习剪辑”中的 `viral_pipeline` 和 `smart_v3` 不是本次 V2，不修改其算法或入口。成片重组继续走原流程。

## V2 的阶段

| 阶段 | 实现 |
|---|---|
| S1/S2 | 直接执行 V1 的原实现，在 S2 完成回调处退出，保证不运行 V1 的 S3/S4。原始子句与被淘汰上下文保留。 |
| S3 | 按原文 ID 和邻句理解素材，整理完整、有具体信息的表达；有用残句保留为待承接片段；明确无用内容淘汰。 |
| S3 补全 | 一次有字符预算的补全调用。脚本搜索邻句和词语相近的其他位置候选，AI判断承接是否成立，允许跨位置和倒序，不改变原意。超过补全容量的碎片仍保留为未解决记录。 |
| S4 | 选择完整表达、去重并编排，附少量备用表达。不能拆表达、改写或随机填充。 |
| S5 | 独立阅读实际拼接文本，核对来源、对象、条件、完整性、垃圾话术、重复和矛盾。失败后最多一次替换/重排，再验收一次。 |
| 渲染 | 只有 S5 通过且指纹有效才渲染；复用原渲染器。分段导出时，同一完整表达的多个原片区间作为一个导出组。 |

脚本负责 ID/时间合法性、S2 禁用区间、唯一合规词源、原文重建、明确搭配条件、已知无效话术、明确断尾、高度重复和真实时长。语义有效性由 AI 判断，脚本不猜代词的商品归属。

如果完整表达候选的原始区间总时长上限已低于目标，直接停止 S4，保留候选供排查，不付费做不可能达标的编排。S5 未通过或时长不足时保存草案和具体问题，停止渲染，不把短版自动标为成功。

本版是文本验收，不包含多模态画面判断；通过文本验收不能保证画面、真实听感和 ASR 边界全部合格。

## 缓存与调用开销

- S3 每批最多 65 条可选子句、约 5,500 字符的主输入，并携带必要原始邻句。无用结构话术先由脚本检查。
- 模型输出 ID 和少量标签，程序生成原文和时长，不让模型重复全文、计算时间或解释每条垃圾句。
- S5 的只读邻句去重后发送，修复复用表达候选，不重跑全量 S3。
- 缓存指纹包括提示词、schema、模型、provider、规则版本和调用限制；相同请求成功缓存复用，失败缓存不自动重试。
- 单节点手动重跑只失效该节点及下游缓存，旧调用归入历史，用量账本继续累计。取消期间已发起但没有返回用量的调用记录为未知，不能当零消耗。
- V2 暂使用 `llm` CLI 引擎，沿用该任务的 provider/model 设置，未修改 V1 引擎设置。Jev 的原契约不支持 V2 的表达结构，使用 Jev 时 V2 会明确报配置错误。

| 环境变量 | 默认值 | 含义 |
|---|---:|---|
| `PIPELINE_V2_MAX_CALLS` | 16 | 任务累计启动调用数量，含失败与手动重跑 |
| `PIPELINE_V2_MAX_OUTPUT_TOKENS` | 64000 | 可观测累计输出用量停止线 |
| `PIPELINE_V2_REQUEST_OUTPUT` | 8000 | WorkBuddy 每请求输出限制；同时检查每次CLI可见及汇总用量 |
| `PIPELINE_V2_PROMPT_CHARS` | 24000 | 单次输入字符上限，超出时停止，不静默截断 |

单次默认超时 240 秒。WorkBuddy 使用独立调用环境、最多两轮、关闭普通重试并设置空流恢复期限，监控可见流式用量并核查最终累计报告。

**这些限制不能保证供应商绝不超额计费。** 已知 CLI 隐藏恢复可能在最终返回时才暴露累计用量。超过停止线会记录失败、阻止后续调用和结果放行，但不能撤回已经发生的消耗。没有把未验证的“low effort”或“推理 token 限额”当作硬保证。

## 验证

执行命令：

```text
python -X utf8 -m unittest discover -s tests -q
node tests/pipeline-v2-ui.test.cjs
node tests/product-ui.test.cjs
```

新增测试覆盖数据库迁移、旧任务保持 V1、任务版本固定、V1/V2 路由、原 S1/S2 复用、跨位置承接、明确条件保护、失败缓存、未知用量、预算停止、S5 未通过禁止渲染、旧验收失效、暂停恢复、完整表达分段导出，以及合成素材的真实 FFmpeg 出片。

本轮最终 Python 全套 325 项测试通过，其中 V2 专项 27 项；草稿/队列原界面测试和 V2 界面测试均通过。V1 管线及 provider 文件相对本轮开始时的 SHA-256 校验一致。未做付费模型质量验收，未修改或重新导出历史任务。

界面测试使用临时 API 数据，覆盖默认 V1、V2 按钮位置、提交期间切换、刷新和重开、旧后台禁用 V2、窄屏无溢出和独立 S5 节点。

[五份1010素材输入容量核查](analysis/v2-input-audit.json)只读既有 S2 产物：S3 为 3–7 批，估算最大输入约 5,839–6,976 字符。本轮没有向模型发送这五份素材，也没有修改原任务或重新导出。该核查不代表真实成片内容已通过发布验收。
