剪映草稿页提供 V1 / V2 / V3。首次打开默认 V1，刷新草稿保留当前选择，整页刷新恢复 V1。按钮只决定后续创建的任务；提交期间切换按钮不会改变已经提交的任务版本。后台未声明支持的版本会禁用。

| --- | --- | --- | --- |
| V1 | 本地 `282f567` | `agent_video/pipeline/` | 原有句单元、提示词、hook 和时长校验，保留直接 API 支持 |
| V2 | 远端 `0365aa7` 的 V2 | `agent_video/pipeline_v2/` | 完整表达整理、编排、独立验收；验收未通过不渲染 |

## 隔离边界

- V1 的整个 `pipeline/` 和原有 `engine/` 文件相对本地基线保持逐字节一致，没有引入远端“原版”禁词。
- V3 使用独立 `badvocab.py` 和 `profiles/douyin-strict.json`；V2 复用 V3 的 S1/S2、词表和渲染器，以保持远端基线规则。V2 不调用 V3 的 S3/S4。
- V3 保留本地的直接 API 传输支持，提示词和选片规则仍来自远端。V2 沿用远端 CLI provider 契约；直接 API 模式会明确报配置错误，不会偷偷回退到其他 provider。
- V3 渲染使用当前本地 Python 运行时入口；现有桌面构建采用内置 Python，未引入远端 Electron 或 frozen 后台入口。
- V1/V3 的任务产物各自在自己的工作目录；V2 的表达、验收、请求缓存和用量还位于任务下的 `v2/` 子目录。
- 共用异常类型和底层 ASR/FFmpeg 等基础设施；版本相关筛选词表不共享可变状态。
- 原有“整片优化剪辑 V3”（`smart_v3`）是另一个功能，不等同于这里草稿模块的 V3，入口和算法均未修改。

## 任务生命周期

数据库新增 `pipeline_version`，历史任务默认 V1，不改历史任务状态或产物。任务创建后版本不可修改，暂停恢复、重试、重置和单节点重跑沿用该版本。V1/V3 为五阶段，V2 另有独立 `review` 阶段。任务队列和详情显示版本。

API 的普通素材和剪映草稿创建都接受 `pipeline_version: v1|v2|v3`，省略时默认 V1。成片重组保持 V1，提交 V2/V3 明确拒绝。分段导出根据版本选择渲染实现，V2 的完整表达导出分组保持不变。

## 启用

先等待正在执行的任务完成，再重启当前后台以加载新代码。仅更新前端不能启用新增版本。现有安装包需要重新打包才能包含新代码；本次没有重打包或重启生产后台。

本次为选择性引入，未合并远端的云端、移动端、后处理等其他改动。本地原始基线另保存在 `codex/v1-baseline-282f567` 分支。
