# AI JSON 返回与断点恢复

V1 与 V3 的公共调用边界统一向所有 CLI 模型和直接 API 模型发送 JSON Schema 及明确的提交要求，不按 hy3 等模型名称分支。CLI 优先使用原生结构化提交，程序继续执行各阶段的字段、类型、ID 完整性与业务校验。提示词不能保证模型每次成功；非法结果仍明确报错，不猜测缺失内容、不自动换模型或提供方。

S3 保持现有的有限批次重试配置：默认首次失败后重试一次，`PIPELINE_JUDGE_RETRIES=0` 可关闭。已通过校验的批次另存到任务目录的 `judge.checkpoint.json`。同一任务全量重试或单节点重跑时，仅复用指纹一致且重新通过校验的批次，其余批次重新调用。指纹包含输入文本、提示词、商品信息、模型、Schema、引擎、提供方及服务地址；切换这些条件会自动失效。自动模型或自动提供方无法保证实际选择一致，因此不复用。删除 checkpoint 文件可强制重新判定。

旧的 `judge.progress.json` 只有界面展示数据，没有请求指纹，不能作为断点自动导入。恢复从本次更新后生成的 checkpoint 开始。有效缓存批次不计入本次 AI 调用次数。

CLI 结构化返回失败时，错误信息附模型、所需顶层字段和本地诊断文件路径。文件位于用户数据目录的 `diagnostics/ai/`，保留有长度上限且经过凭据文本脱敏的响应片段，不额外采集请求、命令行或环境变量；CLI 响应自身可能回显部分输入。诊断写入失败不遮蔽原始调用错误。

V2 保持自身的请求缓存、用量预算与失败策略，不新增自动调用次数。以上修改需要后台重新加载代码后生效；不会自动中断运行中的任务。现有安装包需要重新打包。
