# V1 S4 口头词清理

在“规则管理 → 口头词清理”人工输入无声调拼音，音节用空格分隔，例如 `wo gao su ni`、`qi shi`、`er qie`、`zhen de`。每条规则选择清理范围“句首”或“全部”。支持备注、编辑、启用、停用和删除。没有内置自动启用的规则，数据保存在当前应用数据目录的 `data/filler_rules.json`。已有中文规则读取时自动转换为拼音，保留 ID、备注和启停状态；缺少范围的旧规则按“全部”处理。

V1 S4 流程开关开启时，保存后在下次执行 V1 S4 时生效。开关关闭时仅保留试匹配，不参与 S4 清理。详见 [V1 规则流程开关](rule-pipeline.md)。S4 完成编排后，将每个入选片段的全文转换为拼音，用与 S2 拼音规则相同的连续音节算法匹配。扫描全部位置，原文和字符位置保留。清理范围决定实际清理哪些命中：“全部”清理片段中每一个可对齐命中；“句首”只清理片段文本开头（命中的口头词前面仅有标点或空白）的命中，句中、句尾命中保留并记录原因。例如 `zhen de` 同时命中“真的”和“真得”；“你这样穿真的显瘦”在“全部”下预览为“你这样穿显瘦”，在“句首”下因为没有句首命中而保持原文。重叠命中合并删除区间，跨标点可连续匹配，数字或英文会打断连续拼音。配置的拼音按全文字面执行，不区分强调词与正文含义。

文字与音视频使用同一份清理结果。仅在命中起止位置与 ASR 词块边界完全对齐时才剪切。句中命中会将原入选片段拆成多个保留区间并拼接；同一 ID 的保留区间在分段导出时仍合并为一个完整交付片段。词块内含有口头词和正文、缺少时间戳、词文无法对齐、边界重叠时，该命中保留并记录原因；同一句内其他可对齐命中仍会清理。清理后没有正文时保留原片段。不会按字数估算时间。

新 V1 S1 在 `clauses.json` 保存词级数据，随 S1 快照缓存复用；旧任务也可以读取已有 `words.json`。缺少词级数据的旧任务会跳过实际剪切，可重新执行 S1 获取词级数据后再执行后续阶段。

S4 将原始入选候选、清理后候选、所有拼音命中、删除区间、保留区间和规则快照写入 `order.json` 的 `filler_cleanup`，并更新 `total_seconds`。清理会减少时长，沿用实际剩余时长出片。`manifest.json` 记录同一份报告。只重渲染会复用已保存切点；修改规则后，需要重新执行 S4 才会生效。没有清理快照的历史编排沿用原剪切行为。

测试区支持：

- 输入文本：展示原文拼音、命中原文及字符位置和清理预览，不验证音视频切点。
- 已完成 V1 任务：读取 S4 入选片段、当前规则与 S1 词级数据，显示原文、实际清理结果、区间、减少秒数及跳过原因；测试不写回任务或成片。
- 选择单条规则：可测试已停用规则，不会启用生产规则。默认测试全部启用规则。

自动化测试（使用临时目录，不修改生产规则或任务）：

```powershell
python -X utf8 -m unittest tests.test_filler_rules
node tests/filler-ui.test.cjs
node tests/rules-ui.test.cjs
```

Python 测试覆盖 CRUD、范围校验、句首与全部清理、任意位置及连续拼音匹配、同音错别字、重叠与多次命中、部分可对齐清理、词级边界、缺失数据、全流程、单节点 S4、规则变更后重渲染、缓存、HTTP 只读任务测试，以及 FFmpeg 合成素材的句首与句中多区间实际输出时长。浏览器测试连接临时真实后端，覆盖保存/编辑/删除/启停、范围保存、文本和任务试测、跳过原因、键盘切换与移动端布局。
